# Contributing to Sloom Studio

Thank you for wanting to help. Sloom Studio is developed by one person and every issue,
test and patch matters.

## Licence and sign-off

Sloom Studio is free software under the GNU General Public License, version 3 or (at your
option) any later version. By contributing you agree to license your contribution under the
same terms and you agree to the Contributor License Agreement in `CLA.md`, which lets the
project keep shipping optional proprietary engine plug-ins alongside the GPL code without
asking every contributor again later.

Every commit must carry a Developer Certificate of Origin sign-off:

```
git commit -s
```

adds `Signed-off-by: Your Name <you@example.com>` to the commit message. That line is your
statement that you wrote the change or have the right to submit it under this licence.

## What is not in this repository

- **Tiltmark**, the physical-media brush engine used by Hane on Android, is proprietary and
  not included. The Image workspace ships with the built-in Studio brush engine. The
  `src/components/ImageEditor/tiltmark/` directory holds only the document-format seam and
  no-op stubs so files created with the engine still open.
- Store keystores, signing material and the Play upload pipeline.
- On-device AI upscaler binaries (Qualcomm QNN and Local Dream) that carried non-free
  licences. The desktop local upscaler downloads free components on demand.

## Getting started

```
npm ci
npm run dev        # web app on Vite
npm run build      # type-check and production bundle
npm test           # vitest
npm run desktop:dev
```

Node 20 or newer. The Android project under `android/` builds with Capacitor; the font asset
pack is generated by `scripts/prepare-android-font-asset-pack.mjs` and is not committed.

## Ground rules

- Keep the four workspaces (Image, Paper, Video, Flow) independent: a change in one must not
  require another to be open.
- Product claims in docs must match what the code does today, not what is planned.
- Tests live next to the code they test. A behaviour change comes with a test change.
- The Flow workspace's generative features stay optional and off by default. Nothing in the
  core workflow may depend on a network service.
