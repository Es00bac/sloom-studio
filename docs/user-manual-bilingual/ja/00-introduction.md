# Sloom Studio 入門

> 現在のマニュアル基準：**Sloom Studio ソース 0.9.16-b**（2026年8月27日検証）。公開中のデスクトップ版とAndroid版は別のビルド表記を持つ場合があります。動作を比較するときは、インストール済みアプリに表示される版を確認してください。

Sloom Studioは、Flowによる自動化、Video編集、レイヤー構造を持つImage編集、Paper出版の4つをつなぐローカルファーストの創作スイートです。ひとつのプロジェクトとSource Libraryを共有するため、素材を別アプリ間で何度も書き出し・読み込みせず、生成、レタッチ、レイアウト、編集へ渡せます。

AIは任意です。プロバイダーを設定しなくても、描画、取り込んだ素材の編集、動画の組み立て、文書の出版ができます。プロバイダーを使う場合は、利用者が設定した資格情報と経路を使います。AI利用クレジットは内蔵されず、要求したプロバイダーやモデルを別のものへ密かに置き換えません。

デスクトップ版は、永続的なファイル保存、ネイティブレンダー、リンク素材、OSメニュー、ローカルサービスを含む最も完全な環境です。Android版も同じ4ワークスペースのプロジェクトモデルを持ち、タッチ/スタイラス、Samsung DeX、標準ファイルピッカー、アクセラレーター/LAN機能に対応します。対応ワークフロー向けのブラウザー経路もありますが、ブラウザーのダウンロードはネイティブファイル保存完了として扱われず、ネイティブ専用操作は利用不可と明示されます。

## 製品とプライバシーの仕組み

- プロジェクトは、利用者が管理する通常の`.sloom`ファイルです。
- Sloomのコンテンツ用アカウントや、Sloomが自動提供するプロジェクトクラウドはありません。
- 任意の共同編集・同期では、利用者が設定して運用するセルフホスト型オーソリティを使います。
- プロバイダー要求では、選択した操作に必要な素材だけを、選択したプロバイダー/エンドポイントへ送ります。
- Play版が接続する限定Sloomサービスは購入確認と永久ライセンス配信のためのもので、プロジェクト保管場所ではありません。
- 必要なランタイム/モデルがインストール済みなら、ローカルまたは資格情報不要の経路を利用できます。

## 4つのワークスペース

### Flow

Flowは、繰り返し使える創作自動化を組む型付きノードグラフです。ノードを追加し、互換性のあるハンドルを接続し、必要な出力を実行します。ランタイムは依存関係を評価し、試行履歴を保持し、入力が変わっていない場合は検証済み結果を再利用します。

Flowでできること：

- 設定したプロバイダーまたはローカル経路で、文字、画像、動画、音声を生成・変換する。
- 変数、リスト、条件、ループ、ファイル、再利用関数からプロンプトや構造化データを作る。
- 上限付きプロンプトバッチ、部分再実行、ローカルスケジュールを動かす。
- 有料要求が端末外へ出る前に、強制力のある支出上限を適用する。
- 資格情報を含まないノードパックを書き出し、プロジェクト/ソース素材をワークスペース間で再利用する。

Flowは接続型を検証し、解決不能な循環、必須入力不足、モデル能力不足、不正なパック、支出上限違反を、別経路の成功として見せず拒否します。

### Video

Videoは、ソース/プログラムモニター、マルチトラックタイムライン、インスペクター、効果、キーフレーム、字幕、音声ツール、スコープ、QC、納品書き出しを備えたノンリニア編集環境です。

Videoでできること：

- ソース素材をリンクまたはコピーし、ビンで整理する。
- ソース範囲指定、挿入/上書き、トリム、分割、リップル、ロール、スリップ、スライド、移動を行う。
- クリップ変形/キーフレーム、速度、マスク、追跡/キーイング、ネスト、マルチカム、字幕、文字起こし編集を行う。
- 音声のミックス、修復、ダッキング、クロスフェード、測定、納品を行う。
- 永続ネイティブキューからレンダーし、条件を満たす単純シーケンスでは直接ハードウェア経路、複雑な作業では一般コンポジターを使う。

プレビューと書き出しは同じ編集済みタイムライン契約を使います。未対応の素材、効果、ハードウェア、納品組み合わせは、結果を密かに変えず具体的な理由を表示します。

### Image

Imageは、選択、マスク、調整、保持編集オブジェクト、描画、レタッチ、カラーマネジメント、互換入出力、生成編集を持つレイヤー型ラスター/ベクター編集環境です。

Imageでできること：

- Studio Brushまたはライセンス対象のTiltmark V3物理メディアエンジンで描く。
- レイヤー、グループ、クリッピング、スマートオブジェクト/フィルター、編集可能な文字/ベクター、マスク、チャンネル、名前付きスナップショットを扱う。
- 精密な選択、変形、塗り、修復、合成、アニメーション、バッチ、写真統合を行う。
- 編集可能な`.slimg`文書を開いて保存し、対応範囲のPSD/XCFを交換する。
- 精度/プロファイル範囲を明示した、限定ネイティブ高ビットRGB/CMYK文書経路を使う。

高ビット/CMYKや複雑な互換経路は、対応契約が正確に成立するときだけネイティブ情報を保持します。未対応の組み合わせは、不可逆な変更を行う前に失敗として止まります。

### Paper

Paperは、コミック、漫画、書籍、雑誌、ZINE、プロ印刷/デジタル出力のための複数ページ出版環境です。

Paperでできること：

- 親ページ、マージン、段、グリッド、フレーム、アンカーオブジェクト、回り込み、連結ストーリーでページ/見開きを作る。
- 横組み/縦組み、ルビ、縦中横、注、参照、目次、索引、変数、GREP/ネストスタイル、ブックを扱う。
- コマ、吹き出し、しっぽ、キャプション、SFXを編集可能な形状として描く。
- 正確なフォント/ICCプロファイルを管理し、プリフライトとソフトプルーフを行う。
- 対応範囲のPDF/X、アクセシブルPDF、EPUB、CBZ/Webコミック、KDP、印刷パッケージ、限定IDML経路を書き出す。

厳格な印刷出力は失敗時に閉じます。管理フォント/プロファイル不足、未対応構造、プリフライト失敗がある場合、適合していると偽った出力は作りません。

## 初回起動と言語

初回起動では英語または日本語を選びます。後から**設定 → インターフェース**で変更できます。ロケールはUIと関連する既定値に影響しますが、既存文書の内容を翻訳しません。

Paperの日本語機能には、右綴じ、縦組み、ルビ、縦中横、圏点、禁則、和文フォント処理があります。個別フォントや出力経路の制限は残るため、Paperはプリフライトで報告します。

## Community版とSloom Studio Pro

**Community版**は個人・非商用利用に無料です。4ワークスペースとStudio Brushを利用でき、作品へ目に見える透かしを置きません。永久アンロックの**Sloom Studio Pro**は商用ライセンスで、現在はTiltmark V3とプロ印刷出力を追加します。また、出力メタデータをライセンス済みとして記録し、起動時通知を外します。

ライセンスキーは同梱公開鍵検証器でローカル検証されます。Play購入経路はキーを配信できますが、通常のローカル検証でプロジェクトや素材をアップロードしません。正確な商用条件はリポジトリのライセンスと購入条件が優先され、この概要だけで決まりません。

版の確認・有効化は**設定 → ライセンス**を開きます。

## ナビゲーション

### ワークスペース操作

上部のアプリケーションクロームには、ワークスペース切り替え、プロジェクト操作、元に戻す/やり直し、各ワークスペースのツール、レイアウト/履歴、状態表示があります。中央キャンバスとコンテキスト操作は切り替わりますが、プロジェクトとSource Libraryは共有されます。

### アプリケーションメニュー

設定で**コンパクト**または**メニューバー**表示を選べます。デスクトップ版はネイティブアプリケーションメニューも公開し、対応Linuxデスクトップではシステムのグローバルメニューへ表示できます。メニューコマンドは現在のワークスペースに応じて変わり、カスタムキーボードショートカットも同じコマンド登録を使います。

### コマンドパレット

`Ctrl+Shift+P`（Windows/Linux）または`Cmd+Shift+P`（macOS）でコマンドを検索できます。文字入力にフォーカスがあるときは通常の編集キーが優先され、入力中のキーをグローバルコマンドが奪いません。

### パネルとレイアウト

ワークスペースパネルはサイズ変更、ドッキング、非表示、および対応環境で別ウィンドウへフロートできます。名前付きレイアウトはパネル配置を保持します。スマホ表示では一部のデスクトップ面を、タッチ向けシートとコンパクト操作へ置き換えます。

## プロジェクトと文書ファイル

| 拡張子 | 用途 |
| --- | --- |
| `.sloom` | Flowグラフ、Source Library、ワークスペース状態、Image/Paper/Videoデータ、プロジェクト設定を含むメインプロジェクト。 |
| `.slimg` | 対応する再編集に必要なレイヤー状態とネイティブ素材を持つImage文書。 |
| `.slppr` | マニフェスト、管理対象文書素材、許可されたフォント/プロファイル、レイアウト状態を持つPaper文書。 |
| `.sloom-script` / `.sloom-script.json` | Source Libraryの読み込み経路が受け付ける移植可能なFlowスクリプト。 |
| `.sloom-provider.json` | 資格情報を含まないプロバイダー/モデルカードパック。読み込み時に検証されます。 |
| `.sloompack` | 対応する読み込み/書き出し面で使う共有プロジェクト/ワークスペースパッケージ。 |

素材は、読み込み方法、容量、プラットフォーム、利用者の選択に応じて、埋め込み/管理、外部リンク、またはセッション限定になります。Source Libraryは永続性と不足素材の状態を表示します。プロジェクトを移動する前に統合/パッケージを行い、必要なリンク素材、フォント、プロファイルが含まれるか移動先から到達できることを確認してください。

## 新規作成、開く、保存、復旧

### 新規作成

**プロジェクト → 新規**（または現在のNew Projectコマンド）で空のプロジェクトを作ります。開いているImage/Paper文書に未保存作業がある場合は、状況に応じて保存、復旧コピー保持、破棄、キャンセルを選ぶ置換フローが表示されます。

### 開く

**プロジェクト → 開く**で`.sloom`を選びます。デスクトップ起動時に最後のプロジェクトを再度開く設定もあります。主ファイルを読めない場合、起動復旧は原本を密かに置き換えず、保持バックアップ、再試行、別ファイル、新規プロジェクトを提示できます。

単独の`.slimg`と`.slppr`は対応ワークスペースで開きます。Paper文書は別タブとして保持でき、単独文書の保存はプロジェクトへフラット化せず編集可能パッケージを書き込みます。

### 保存

デスクトップの**保存**はネイティブトランザクションで現在のプロジェクトを書き込み、成功後だけ完了として扱います。**名前を付けて保存**では新しい場所を選びます。ブラウザー版はプロジェクトコピーをダウンロードしますが、ダウンロードはネイティブファイル保存完了とはみなしません。

自動保存/復旧は、変更が落ち着いた後と重要なライフサイクル境界で上限付きスナップショットを作ります。プロジェクト履歴は名前付きスナップショットと復元を提供します。復旧は意図的なバックアップの代わりではありません。重要な`.sloom`、`.slimg`、`.slppr`は別のバックアップ先にも保管してください。

### スクラッチ/プロジェクトフォルダー

デスクトップのプロジェクトフォルダーは、ネイティブメディア処理のスクラッチ、キャッシュ、出力を所有します。別の場所が必要なら**スクラッチフォルダーを設定**またはProject Library操作を使います。リンク原本を移動・削除するとオフラインになるため、シリアライズ済みパスを手編集せず再リンク/統合を使ってください。
